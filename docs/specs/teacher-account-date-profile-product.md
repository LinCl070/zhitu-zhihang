# 教师账号资料与统一日期选择需求规范

> **功能名称：** 教师账号完整资料与学生/教师日期选择
> **版本：** v1.0
> **状态：** 审查中
> **作者：** 项目负责人 + Codex
> **最后更新：** 2026-09-14

## 1. 概述

管理员创建教师账号时，应一次填写用户名、教师身份、联系电话、联系邮箱、入职日期和密码。教师入职日期与学生入学日期均使用同一个日历日期选择组件，选择精确到年、月、日，并由后端保存完整日期。

本规范中的“教师身份”解释为教师姓名/身份名称，继续存入既有 `users.display_name`，账号角色仍由服务端固定为 `counselor`，管理员不能通过请求改变角色。

## 2. 用户故事与验收标准

### US-001：管理员创建完整教师账号

**作为** 管理员，**我希望** 在同一表单中填写教师的完整账号资料，**以便** 创建可直接登录且可识别的教师账号。

- **AC-001.1:** GIVEN 管理员进入教师账号面板，WHEN 查看创建表单，THEN 显示用户名、教师身份、联系电话、联系邮箱、入职时间、密码六个必填字段，标签含红色 `*`。
- **AC-001.2:** GIVEN 六个字段均合法，WHEN 管理员提交，THEN 服务端创建角色固定为 `counselor` 的账号，保存姓名、电话、邮箱和完整入职日期，并以安全哈希保存密码。
- **AC-001.3:** GIVEN 用户名已存在，WHEN 管理员提交，THEN 返回 `409` 和“用户名已被使用”，不创建账号。
- **AC-001.4:** GIVEN 电话、邮箱、日期或密码不合法，WHEN 管理员提交，THEN 返回可读校验错误，不创建账号。
- **AC-001.5:** GIVEN 非管理员用户，WHEN 调用教师创建接口，THEN 返回 `403`，不泄露请求中的教师资料。
- **AC-001.6:** GIVEN 教师创建成功，WHEN 管理台账刷新，THEN 新教师出现在教师列表中，创建表单被清空，页面不再显示由系统生成的临时密码。

### US-002：使用日历选择教师入职日期

**作为** 管理员，**我希望** 点击日历小卡片选择教师入职日期，**以便** 准确填写年、月、日。

- **AC-002.1:** GIVEN 入职时间字段可用，WHEN 用户点击字段或日历图标，THEN 打开浏览器原生日历面板并允许选择具体年月日。
- **AC-002.2:** GIVEN 用户选择日期，WHEN 日历关闭，THEN 字段显示所选日期并将 ISO 日期 `YYYY-MM-DD` 作为提交值。
- **AC-002.3:** GIVEN 用户只使用键盘，WHEN 聚焦日期字段，THEN 可完成日期选择和提交，焦点样式清晰可见。

### US-003：学生注册使用相同日期组件

**作为** 学生，**我希望** 注册时通过相同的日历组件选择入学日期，**以便** 填写精确且一致的入学时间。

- **AC-003.1:** GIVEN 学生进入注册模式，WHEN 查看入学时间字段，THEN 原年份滚轮被统一日期组件替代，字段为必填。
- **AC-003.2:** GIVEN 学生选择合法日期并完成其他必填字段，WHEN 注册成功，THEN 服务端保存 `enrollment_date`，并从该日期派生 `enrollment_year` 以兼容现有读取链路。
- **AC-003.3:** GIVEN 已有学生只有 `enrollment_year`，WHEN 工作台读取该学生，THEN 仍显示既有年份，不根据年份伪造具体年月日。

## 3. 非功能性需求

| ID | 类别 | 描述 | 目标指标 |
|:---|:---|:---|:---|
| NFR-001 | 安全 | 密码只发送到认证接口并以既有密码策略校验、哈希；不得进入日志、响应或审计元数据。 | 明文密码零持久化、零回显 |
| NFR-002 | 隐私 | 教师电话、邮箱和入职日期只用于账号管理，不进入岗位匹配、FastGPT 提示词或审计元数据。 | 隐私定向测试覆盖禁止路径 |
| NFR-003 | 可用性 | 两个页面复用同一日期组件，支持鼠标、触摸和键盘。 | Chrome/Edge 桌面与 375px 窄屏可用 |
| NFR-004 | 数据质量 | 日期必须为有效 ISO 日期且不得晚于提交当天。 | 前后端均限制，服务端为最终判定 |
| NFR-005 | 兼容性 | 历史 `enrollment_year` 数据继续可读。 | 现有学生列表不因迁移丢失入学信息 |

## 4. 约束与假设

### 约束

- 教师账号角色由服务端固定为 `counselor`，不接受客户端传入角色。
- 教师身份使用现有 `display_name` 字段保存，不新增同义姓名字段。
- 联系电话沿用现有中国大陆 11 位手机号规则；邮箱沿用现有邮箱校验规则。
- 密码沿用现有强度规则；创建后教师首次登录仍须修改密码，以保持既有账号安全策略。
- 入职日期与入学日期范围为 `1958-01-01` 至提交当天。
- 新学生写入完整 `enrollment_date`，同时维护派生字段 `enrollment_year`；旧记录不回填虚构日期。

### 假设

- “教师身份”指教师姓名/身份名称，而不是身份证号码、教师资格证号或职称。
- “日历小卡片”指点击后弹出的浏览器原生日期选择面板，不引入第三方日期库。
- 管理员填写的是教师初始密码，账号创建后通过既有 `must_change_password` 机制要求教师首次登录修改。

## 5. 超出范围

- 身份证号码、教师资格证号、职称、院系和工号管理。
- 编辑已创建教师的资料、批量导入教师和删除教师。
- 手机/邮箱验证码、通知发送和密码找回。
- 将教师或学生联系方式用于模型、匹配、推荐或外部平台同步。
