# 需求规范 (Product Specification)

> **功能名称：** Web 端复用 FastGPT 连续会话
> **版本：** v1.0
> **状态：** 草稿
> **作者：** AI Architect + Human Engineer
> **最后更新：** 2026-09-11

## 1. 概述

让项目 Web 端的职业准备和就业政策咨询更接近 Agent Builder 测试页的连续对话效果。当前后端每次请求生成新的 `chatId`，FastGPT 无法使用上一轮上下文；本功能将为每个登录用户和咨询类型复用独立会话标识，同时保持现有画像变量、服务端密钥隔离和人工确认提示。

## 2. 用户故事与验收标准

### US-001: 连续咨询上下文

**作为** 学生，**我希望** 连续提问时 FastGPT 能参考上一轮对话，**以便** 获得与测试页类似的完整回答。

#### 验收标准

- **AC-001.1:**
  - **GIVEN** 同一登录用户连续使用同一咨询类型
  - **WHEN** 提交两次或以上问题
  - **THEN** 后端向 FastGPT 复用同一个该用户专属 `chatId`。

- **AC-001.2:**
  - **GIVEN** 用户切换“职业准备”和“就业政策”
  - **WHEN** 分别提交问题
  - **THEN** 两种类型使用不同的会话，不发生上下文串线。

### US-002: 会话隔离与安全降级

**作为** 项目负责人，**我希望** 连续会话不会跨用户泄露，且无来源回答仍有人工确认提示。

#### 验收标准

- **AC-002.1:** 不同用户或服务重启后不会复用同一个会话标识。
- **AC-002.2:** API 调用失败、无回答或无来源时，现有错误处理和人工确认标识保持不变。
- **AC-002.3:** 浏览器不会接收 API Key、应用 ID 或原始平台响应。

## 3. 非功能性需求

| ID | 类别 | 描述 | 目标指标 |
|:---|:---|:---|:---|
| NFR-001 | 隔离 | 会话按用户和咨询类型隔离。 | 零跨用户/跨类型复用 |
| NFR-002 | 兼容性 | 不改变现有咨询请求字段和响应字段。 | 现有前端无需迁移 |
| NFR-003 | 生命周期 | 会话仅保存在服务端进程内，重启后自然失效。 | 无持久化敏感数据 |
| NFR-004 | 性能 | 连续提问不增加上游请求次数。 | 每个问题一次请求 |

## 4. 约束与假设

### 约束

- 使用现有 FastGPT Chat Completions API 和应用 ID。
- 不向 FastGPT 发送学生姓名、学号、电话、邮箱等身份档案。
- 不把客户端提交的任意会话标识直接作为跨用户凭据。

### 假设

- Agent Builder 测试页的差异主要来自连续 `chatId` 和会话上下文；若其使用草稿或内部接口，Web 端只能实现行为接近而非字节级一致。
- 现有 `AssistantService` 仍负责无来源回答的人工确认提示。

## 5. 超出范围

- 修改 FastGPT 应用提示词、知识库或发布状态。
- 持久化聊天记录到 PostgreSQL。
- 保证每次模型输出文字完全一致。
