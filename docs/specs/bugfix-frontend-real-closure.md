# Bugfix: 恢复前端真实业务闭环

## 1. 缺陷摘要

最近一次前端工作台重构后，页面保留了新的界面与交互，但业务操作重新使用 React 内存状态、固定示例岗位和 `setTimeout` 模拟结果。后端已有的 PostgreSQL、演示会话、岗位匹配、行动计划、教师协助和 SF-FastGPT 接口未被页面调用，导致“看起来成功”的操作不会持久化，也无法体现真实平台能力。

## 2. 当前证据

- `frontend/src/App.tsx` 的画像保存、岗位刷新和行动计划生成均使用 `setTimeout` 与 `INITIAL_*` 常量。
- `frontend/src/components/AdvicePanel.tsx` 使用固定关键词回复，没有调用 `/api/v1/assistant/query`。
- `frontend/src/StaffDashboard.tsx` 使用固定教师/管理员数据，意见与授权变更只写入前端状态。
- `frontend/src/api/client.ts` 目前仅公开 `startDemo`，虽然保留 fallback，但没有画像、匹配、计划、咨询和 staff API 方法。
- 后端 `POST /api/v1/matches` 在当前 PostgreSQL 中可返回 10 条岗位；页面仍展示 3 条固定岗位。
- 后端 `POST /api/v1/assistant/query` 的 career 与 policy 路由当前均能进入 `sf_fastgpt`，但返回无来源时安全降级为人工确认；该状态必须原样反映到页面，不能伪造智能回答。
- 后端 `MatchResponse` 当前没有前端所需的 `reasons` 字段，展开匹配依据前必须统一契约。

## 3. 修复目标

1. 学生进入演示时使用服务端签发的真实短期 Bearer 会话。
2. 学生画像保存调用 `PUT /api/v1/career-profile/me`，成功后调用 `POST /api/v1/matches`，推荐结果与当前画像一致。
3. 岗位推荐使用后端返回的真实 PostgreSQL 匹配结果，展示来源链接、公开/模拟标识和安全空结果状态。
4. 生成行动计划调用 `POST /api/v1/action-plans`，结果在刷新页面后仍可从后端恢复；前端与后端统一匹配结果字段。
5. 就业咨询调用 `POST /api/v1/assistant/query`，区分 career/policy 路由，展示来源、运行模式、免责声明和转人工状态。
6. 教师和管理员页面调用已有 staff/demo API；教师意见、管理员授权和审计数据不再只保存在浏览器内存。
7. 网络错误、401/403、409、FastGPT 无来源和数据库异常均显示可操作提示，不使用固定成功数据掩盖失败。

## 4. 范围与非目标

### 4.1 本次范围

- 前端 API 类型、请求封装、会话状态和学生工作台数据流。
- 后端匹配响应与前端展开依据所需的最小字段补齐。
- 学生、教师、管理员已有接口的页面接入。
- 针对真实 API 链路的前端构建、后端回归和浏览器关键路径验证。

### 4.2 非目标

- 不新增学校统一身份认证，不接入学校生产数据库。
- 不改变匹配权重、岗位来源审核规则、教师可见范围或 FastGPT 安全降级策略。
- 不把平台密钥、工作流 ID、数据库连接串下发到浏览器。
- 不新增自动投递、录用预测、简历原文存储或敏感画像字段。
- 不保留“请求失败后静默返回固定业务成功结果”的 fallback 行为；离线 fallback 只能用于不依赖业务数据的开发启动页，不能伪造业务结果。

## 5. 期望行为与验收标准

### AC-01 会话

GIVEN 用户在入口选择学生、教师或管理员，WHEN 请求成功，THEN 页面保存服务端返回的 `access_token`、显示名称和角色，并使用该 token 请求后续 API；WHEN 请求失败，THEN 显示失败提示且不进入工作台。

### AC-02 学生画像与推荐

GIVEN 学生修改目标岗位，WHEN 保存画像成功，THEN 页面先清空旧推荐，再用当前画像请求匹配并展示新结果；WHEN 匹配失败，THEN 保留已保存状态、清空或标记旧推荐，并允许手动重试。

### AC-03 数据真实与来源

GIVEN 后端返回岗位列表，WHEN 页面展示推荐，THEN 不使用 `INITIAL_JOBS` 替换接口结果；每条岗位展示 `score`、缺口、来源标题、发布日期、有效期和可用来源链接；无结果时展示后端消息和转人工提示。

### AC-04 行动计划

GIVEN 学生点击某条推荐的行动计划，WHEN 请求成功，THEN 展示后端返回的计划项；刷新或重新进入时可按当前会话恢复已有计划或明确显示尚未生成，不显示与目标岗位无关的固定后端计划。

### AC-05 咨询

GIVEN 学生提交职业或政策问题，WHEN 请求成功，THEN 展示后端回答、来源、免责声明、`mode` 和 `handoff_recommended`；WHEN 无可信来源或平台失败，THEN 明确提示人工确认，不展示本地固定回答冒充模型结果。

### AC-06 角色工作台

GIVEN 教师或管理员进入工作台，WHEN API 返回数据，THEN 页面展示服务端授权范围内的数据；教师提交意见、管理员创建授权后，重新读取页面可看到持久化结果；越权或会话过期时返回明确错误并回到角色入口。

### AC-07 安全与回归

任何前端构建产物、网络请求和错误提示都不得包含 API Key、工作流 ID、数据库 URL、完整学生隐私字段或原始平台错误响应。

## 6. 修复设计

### 6.1 前端会话边界

`AppContent` 持有当前 `DemoSession`，入口调用 `api.startDemo(identity)`；所有业务请求显式携带该 token。退出时清理会话与业务状态。认证失败统一清除 token 并返回角色选择页。

### 6.2 API 客户端

在 `frontend/src/api/client.ts` 增加类型化方法：`startDemo`、画像读写、匹配、行动计划、咨询、教师摘要/意见、管理员授权/台账/审计。请求层只对网络不可达提供错误对象，不将业务接口失败转换为固定成功响应。

### 6.3 学生数据流

保存画像采用“保存画像 -> 重新匹配”的顺序。画像字段按逗号/换行转为后端列表；匹配请求默认 `limit=10`。每次新画像保存或手动刷新都丢弃旧列表，并使用最新响应替换。

### 6.4 FastGPT 展示

咨询组件接收当前 token 和咨询类型，响应消息按 `answer`、`sources`、`mode`、`handoff_recommended` 分层展示。`sources` 为空时保留后端人工确认语义，不能由前端补造来源或答案。

### 6.5 响应契约

后端 `MatchResponse` 增加可解释依据字段时保持向后兼容；字段来源必须是已存储的规则结果或岗位信息，不允许由前端推测。前端对缺失可选字段安全渲染为空列表。

### 6.6 教师与管理员

先接入现有 API，不扩大权限：教师只读已授权摘要和本人意见，管理员只读脱敏台账并维护固定演示授权。页面数据加载、提交和失败状态均显式处理。

## 7. 风险与验证

- 高风险区域：身份会话、RBAC、PostgreSQL 持久化、SF-FastGPT 外部调用。
- 后端：运行现有 unittest 与 Ruff，并增加响应契约和真实 HTTP 链路测试。
- 前端：运行 ESLint、TypeScript/Vite build；用浏览器验证三角色登录、画像保存、目标岗位变更、推荐、行动计划、咨询和退出。
- 数据安全：扫描前端源码与构建产物，不出现 `.env` 值；检查失败响应不会泄露平台原始错误。
