# 分角色账号登录需求规范

> **功能名称：** 职途智航分角色账号登录
> **版本：** v1.0
> **状态：** 审查中
> **关联现有规范：** `docs/specs/product.md`、`docs/specs/architecture.md`
> **最后更新：** 2026-09-09

## 1. 概述

将当前按角色直接进入的演示会话替换为账号+密码登录。学生可以自助注册，教师账号只能由管理员创建，管理员账号只能通过部署初始化创建；登录后的角色由服务端账号记录决定，前端不能自行提升权限。

## 2. 用户故事与验收标准

### US-LOGIN-001: 用户登录

**作为** 已注册用户，**我希望** 使用用户名和密码登录，**以便** 进入与账号角色匹配的工作台。

- **AC-LOGIN-001.1:** GIVEN 已存在且启用的账号，WHEN 提交正确用户名和密码，THEN 返回短期会话令牌和服务端确定的角色，并进入对应工作台。
- **AC-LOGIN-001.2:** GIVEN 用户名不存在、密码错误或账号被禁用，WHEN 提交登录，THEN 返回统一的失败提示，不透露账号是否存在。
- **AC-LOGIN-001.3:** GIVEN 会话令牌缺失、无效或过期，WHEN 访问受保护接口，THEN 返回 401 并回到登录页。
- **AC-LOGIN-001.4:** GIVEN 已登录用户尝试访问其他角色接口，WHEN 服务端鉴权，THEN 返回 403 并记录脱敏审计事件。

### US-LOGIN-002: 学生注册

**作为** 未注册学生，**我希望** 自助创建学生账号，**以便** 使用职业规划功能。

- **AC-LOGIN-002.1:** GIVEN 注册信息通过校验且用户名未占用，WHEN 提交注册，THEN 创建 `student` 账号并要求使用密码登录。
- **AC-LOGIN-002.2:** GIVEN 注册请求试图指定 `counselor` 或 `admin` 角色，WHEN 服务端处理，THEN 拒绝请求；角色不能由客户端决定。
- **AC-LOGIN-002.3:** GIVEN 用户名已存在或密码不符合规则，WHEN 提交注册，THEN 返回字段级错误且不创建账号。

### US-LOGIN-003: 管理员管理教师账号

**作为** 管理员，**我希望** 创建、禁用和重新启用教师账号，**以便** 控制就业指导工作台的访问范围。

- **AC-LOGIN-003.1:** GIVEN 已登录管理员，WHEN 创建教师账号，THEN 账号角色固定为 `counselor`，初始密码只展示一次并要求首次登录修改。
- **AC-LOGIN-003.2:** GIVEN 非管理员或未登录用户，WHEN 调用教师账号管理接口，THEN 返回 401/403，不产生账号变更。
- **AC-LOGIN-003.3:** GIVEN 部署初始化参数有效，WHEN 首次初始化管理员账号，THEN 创建唯一 `admin` 账号；网页注册接口不允许创建管理员。

### US-LOGIN-004: 修改与重置密码

**作为** 学生或教师，**我希望** 修改或在忘记密码时重置密码，**以便** 保持账号可用和安全。

- **AC-LOGIN-004.1:** GIVEN 已登录学生、教师或管理员，WHEN 提交当前密码和符合规则的新密码，THEN 更新密码哈希并使旧会话失效。
- **AC-LOGIN-004.2:** GIVEN 管理员为学生或教师发起密码重置，WHEN 重置成功，THEN 生成一次性临时密码/凭据并要求目标账号下次登录修改。
- **AC-LOGIN-004.3:** GIVEN 临时密码已使用、过期或输入错误，WHEN 尝试登录，THEN 拒绝登录并提示重新联系管理员。
- **AC-LOGIN-004.4:** GIVEN 用户提交新密码与确认密码不一致、过短或命中禁止规则，WHEN 修改/重置，THEN 拒绝更新并保留旧密码。

## 3. 非功能性需求

| ID | 类别 | 描述 | 目标指标 |
|:---|:---|:---|:---|
| NFR-LOGIN-001 | 安全 | 仅保存强密码哈希和随机盐，不保存明文密码、临时密码或会话令牌。 | 仓库、响应和审计中无明文凭据 |
| NFR-LOGIN-002 | 安全 | 登录失败使用统一提示并具备基础限流/锁定策略。 | 连续失败不会泄露账号存在性 |
| NFR-LOGIN-003 | 隐私 | 审计仅记录角色、操作、账号标识和时间，不记录密码或完整请求体。 | 100% 认证审计脱敏 |
| NFR-LOGIN-004 | 兼容性 | 登录、注册和密码页支持最新 Chrome/Edge 与移动窄屏。 | 无水平溢出，键盘可完成核心流程 |
| NFR-LOGIN-005 | 可用性 | 认证失败、会话过期和首次改密状态有明确反馈。 | 核心错误状态有可读提示 |

## 4. 约束与假设

### 约束

- 不保留当前 `demo/sessions` 角色直达入口及演示账号。
- 角色权限必须由服务端账号记录和现有 RBAC 校验决定。
- 管理员不得通过网页注册；管理员初始化凭据只来自部署环境或一次性运维命令。
- 不在本期引入邮箱、短信或学校 SSO 依赖。

### 假设

- 用户名全局唯一、大小写不敏感；密码至少 8 位，并要求包含字母和数字。
- “密码重置”采用管理员辅助的一次性临时密码方案；未来接入邮箱/短信/SSO 时替换恢复流程。
- 会话仍为短期 Bearer 令牌，服务重启后失效；令牌不写入业务数据库。

## 5. 超出范围

- 邮箱/短信验证码、自助找回密码和学校统一身份认证。
- 多因素认证、社交登录、组织级批量导入。
- 一个账号绑定多个角色或登录后切换角色。
