# 学生注册迁移遗漏修复规范

> **问题名称：** 认证迁移未应用导致学生注册失败
> **版本：** v1.0
> **状态：** 审查中
> **严重级别：** P1
> **影响环境：** 当前本地运行环境
> **最后更新：** 2026-09-09

## 1. 问题概述

后端已部署学生注册接口和认证模型，但当前数据库仍停留在认证迁移之前的 schema。所有提交有效注册信息的学生都会在数据库访问认证字段时失败。

## 2. 证据与复现

- 运行中的 `POST /api/v1/auth/register/student` 已出现在 OpenAPI 文档中。
- 使用运行后端同一虚拟环境进行只读 schema 检查，`users` 只有 `id`、`display_name`、`role`、`created_at`，缺少 `username`、`password_hash`、`is_active`、`must_change_password`、`failed_login_count`、`locked_until` 和 `password_changed_at`。
- 认证字段和 `password_reset_tokens` 由现有 Alembic revision `20260909_0004` 定义。

## 3. 当前错误行为

### BUG-REG-001: 注册接口依赖不存在的认证列

- **WHEN** 未注册学生提交符合规则的用户名、显示名称和密码。
- **THEN** 服务端在访问或写入认证字段时失败，学生账号不会创建。

## 4. 修复后的期望行为

### FIX-REG-001: 应用既有认证迁移

- **WHEN** 对当前数据库执行 revision `20260909_0004`。
- **THEN** `users` 具备认证列，`password_reset_tokens` 表存在，学生注册可返回 `201`。

## 5. 必须保持不变的行为

- 迁移只增加既有认证设计中定义的 schema，不重置或删除现有业务数据。
- 注册接口仍只能创建 `student` 账号，管理员和教师创建边界不改变。

## 6. 范围与约束

### 修复范围内

- 使用 `backend/.venv` 的 Alembic CLI 执行已有迁移。
- 对迁移后 schema 和一次学生注册请求做最小验收。

### 明确不在范围内

- 修改认证接口、密码策略、前端注册表单或已有业务数据。

### 约束与假设

- 当前 `DATABASE_URL` 指向用户运行项目的本地数据库。
- 执行迁移前必须保留现有数据；如迁移报错，立即停止并报告，不做手工 schema 修改。

## 7. 风险与回滚提示

- **主要风险：** 迁移对已有用户行填充不可登录的 legacy 占位凭据，旧演示身份不能再直接登录。
- **回滚方式：** Alembic downgrade 至 `20260723_0003`，仅在确认未有基于新认证列创建的账号时使用。
- **观察指标：** 注册接口 HTTP 状态、后端异常日志、`users` 认证列存在性。
