# 需求规范 (Product Specification)

> **功能名称：** 展示无结构化来源的 SF-FastGPT 回答
> **版本：** v1.0
> **状态：** 已批准
> **作者：** AI Architect + Human Engineer
> **最后更新：** 2026-09-11

## 1. 概述

当 SF-FastGPT 已返回有效回答文本、但 Chat Completions API 未提供结构化来源时，学生端应展示该回答，而不是替换为固定兜底文案。页面必须同时保留醒目的人工确认提示和免责声明，不能将无来源回答表示为已核验资料。

## 2. 用户故事与验收标准

### US-001: 查看真实平台回答

**作为** 已登录学生，**我希望** 在职业准备或就业政策咨询中看到 SF-FastGPT 实际返回的回答，**以便** 获得可继续追问的准备建议。

#### 验收标准

- **AC-001.1:**
  - **GIVEN** 后端以 `sf_fastgpt` 模式收到非空回答，且来源列表为空
  - **WHEN** 学生提交咨询问题
  - **THEN** API 返回原回答文本、空来源列表、`handoff_recommended=true`，并附带“平台未返回可核验来源，请人工确认”的免责声明。

- **AC-001.2:**
  - **GIVEN** 前端收到上述 API 响应
  - **WHEN** 渲染咨询消息
  - **THEN** 显示原回答、“建议人工确认”标识和免责声明；不得渲染虚构的来源链接。

### US-002: 保持不可信场景的安全降级

**作为** 项目负责人，**我希望** 平台不可用或没有回答时继续返回人工确认建议，**以便** 不将错误或空内容展示为建议。

#### 验收标准

- **AC-002.1:**
  - **GIVEN** 平台 HTTP 调用失败、响应格式无效或缺少回答文本
  - **WHEN** 学生提交咨询问题
  - **THEN** 系统保留既有固定人工确认回复，且不暴露平台错误详情。

- **AC-002.2:**
  - **GIVEN** 模拟模式
  - **WHEN** 学生提交咨询问题
  - **THEN** 系统继续返回既有模拟模式人工确认回复。

## 3. 非功能性需求

| ID | 类别 | 描述 | 目标指标 |
|:---|:---|:---|:---|
| NFR-001 | 安全 | 浏览器、日志和响应中不得包含 API Key、应用 ID、请求头或原始平台响应。 | 零敏感字段暴露 |
| NFR-002 | 兼容性 | 不变更现有咨询 API 字段和前端类型。 | 现有调用方无需迁移 |
| NFR-003 | 可信度 | 无来源回答必须标记为建议人工确认。 | 每次无来源真实回答均有标识 |
| NFR-004 | 性能 | 不增加额外的平台请求。 | 单次咨询仍为一次上游调用 |

## 4. 约束与假设

### 约束

- 只适用于 `sf_fastgpt` 成功返回非空文本的场景。
- 不解析、拼接或伪造回答正文内的资料名称、链接、版本或日期。
- 不修改 FastGPT 平台应用、数据库 schema、认证授权或前端 API 合同。

### 假设

- 前端现有消息组件已能显示回答、`handoff_recommended` 标识和免责声明。
- 真实平台继续以 OpenAI 兼容的 `choices[0].message.content` 提供回答。

## 5. 超出范围 (Out of Scope)

- 让 FastGPT API 返回结构化来源，或修改平台工作流。
- 将无来源回答认定为官方就业政策、招聘承诺或审核通过资料。
- 自动申请岗位、采集真实学生数据或向模型传递身份档案。
